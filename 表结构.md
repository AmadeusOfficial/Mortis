# 表结构

SQLite。所有表由基地建立。插件新增数据类型时，只往 `data_types` 和 `type_fields` 写行，不加列，不建表，不写迁移。

设计参考 Amane（`field_sources`、`locked_fields`、按来源保存原始结果）、Plex（一张主表装所有类型，`parent_id` 串起季和集，多值字段进通用标签表）和 Jellyfin（外部编号单独一张表，以条目和来源为主键）。

## 命名规则

- 表名用复数蛇形：`items`、`media_files`。
- 外键写成 `单数表名_id`：`item_id`、`person_id`、`library_id`。
- 时间写成 `xxx_at`，日期写成 `xxx_date`，布尔写成 `is_xxx` 或 `has_xxx`。
- 列名直接叫它存的东西：`title`、`overview`、`poster_path`。不用 `entity`、`role`、`card`、`scheme` 这类抽象词。
- JSON 列的名字说明里面是什么：`fields`、`field_sources`、`locked_fields`、`raw`。

## 值放在哪里

一个字段只放在一个地方，由 `type_fields.stored_in` 决定：

| stored_in | 放在哪里 | 适合的字段 |
|---|---|---|
| `items_column` | `items` 的共有列 | 标题、原名、剧情、日期。每种类型都有意义 |
| `tags` | `tags` 和 `item_tags` | 类型、制片公司、国家、品牌、平台这类多值字段 |
| `people` | `people` 和 `item_people` | 导演、演员、编剧、声优 |
| `images` | `item_images` | 同人画、横幅、透明标志、季海报、剧照 |
| `ratings` | `item_ratings` | IMDb、TMDB、豆瓣等多个来源的评分 |
| `fields` | `items.fields`（JSON） | 只属于某个类型、又不需要筛选的单值字段：时长、分级、引擎 |

筛选只走前五种。`fields` 里的键不能拿来筛选；要筛选，就把这个字段声明到 `tags`。

## 类型声明

```sql
create table data_types (
  id text primary key,                     -- movie、tv、anime、galgame
  name text not null,                      -- 电影
  structure text not null,                 -- item、item_group、series
  subtitle_field text,                     -- 海报墙卡片第二行取哪个字段，如 original_title、brands
  plugin_id text,                          -- 内置类型为空
  is_enabled integer not null default 1,
  check (structure in ('item', 'item_group', 'series'))
);

create table type_fields (
  data_type_id text not null references data_types (id),
  field_key text not null,                 -- title、genres、runtime
  label text not null,                     -- 片名、类型、时长（分钟）
  value_type text not null,
  stored_in text not null,
  column_name text,                        -- stored_in = items_column 时：items 的列名
  tag_kind text,                           -- stored_in = tags 时：genre、studio、brand
  person_role text,                        -- stored_in = people 时：director、actor、voice
  image_kind text,                         -- stored_in = images 时：fanart、banner、clearlogo
  applies_to text not null default 'work', -- 这个字段属于哪一层：collection、work、season、episode
  detail_section text not null,            -- 详情页分区：基本信息、演职员、图片
  position integer not null,
  is_lockable integer not null default 1,
  is_filterable integer not null default 0,
  is_sortable integer not null default 0,
  primary key (data_type_id, applies_to, field_key),
  check (value_type in ('text', 'longtext', 'number', 'date', 'rating', 'people', 'tags', 'images', 'url')),
  check (stored_in in ('items_column', 'tags', 'people', 'images', 'ratings', 'fields')),
  check (applies_to in ('collection', 'work', 'season', 'episode'))
);
```

安装时由程序校验：`stored_in` 对应的那一列必须有值；`items_column` 只能指向下面 `items` 里列出的共有列；`is_filterable = 1` 的字段不能放在 `fields`；`is_sortable = 1` 的字段只能放在 `items_column` 或 `ratings`。校验不通过就拒绝安装。

## 库

```sql
create table libraries (
  id integer primary key,
  data_type_id text not null references data_types (id),
  name text not null,                      -- 电影、电视剧、动漫
  automation text not null default 'manual',
  is_auto_scrape integer not null default 1,  -- 扫描完是否接着刮削
  wall_collections text not null default 'collapse',  -- 海报墙怎么显示系列电影
  created_at text not null,
  updated_at text not null,
  check (automation in ('manual', 'watch', 'schedule')),
  check (wall_collections in ('movies', 'both', 'collapse'))
);

create table library_paths (
  id integer primary key,
  library_id integer not null references libraries (id) on delete cascade,
  path text not null unique                -- M:\plex\movie
);
```

电视剧和动漫都是 `series` 结构，但分属两个库。`automation`：`manual` 只手动扫描，`watch` 发现新文件就整理，`schedule` 按 `schedules` 里的计划扫描。刮削、重命名、NFO 等设置存在配置文件里，按数据类型分节，不进这几张表。`is_auto_scrape` 为 1 时，扫描认出电影后接着刮削还没刮削过的条目；为 0 时只扫描和识别。手动扫描时可以临时指定一次。

`wall_collections` 是按结构的海报墙显示设置，不是某种类型的业务字段，只对 `item_group` 结构（单条目加分组）的库生效；其他结构的库保持默认值、不读这一列。`movies` 只显示电影；`both` 系列和其中每部电影都显示；`collapse` 把库里有两部及以上的系列收成一张系列卡片，只有一部的系列直接显示那部电影。`collapse` 的库有搜索词时按 `both` 显示，`movies` 搜索时仍只显示电影。库的电影计数只算 `work`。

## 条目

```sql
create table items (
  id integer primary key,
  library_id integer not null references libraries (id),
  data_type_id text not null references data_types (id),
  parent_id integer references items (id) on delete cascade,
  kind text not null,                      -- collection、work、season、episode
  index_number integer,                    -- 季号、集号；系列里第几部
  title text not null,
  original_title text,
  sort_title text,
  subtitle text,                           -- 海报墙第二行，按 data_types.subtitle_field 生成
  overview text,
  release_date text,                       -- ISO 日期；剧集是首播，集是播出日
  poster_path text,                        -- 本地海报文件
  fields text not null default '{}',       -- JSON，键必须在 type_fields 里且 stored_in = fields
  field_sources text not null default '{}',-- JSON：{"title":"manual","overview":"douban"}
  locked_fields text not null default '[]',-- JSON：["title"]
  created_at text not null,
  updated_at text not null,
  check (kind in ('collection', 'work', 'season', 'episode'))
);

create index ix_items_wall on items (library_id, parent_id, release_date);
create index ix_items_parent on items (parent_id, index_number);
```

每种结构允许的层级：

| structure | 允许的 kind | 例子 |
|---|---|---|
| item | work | 一款 Galgame |
| item_group | collection；work 的 parent 为空或指向 collection | 一部电影、一个系列电影 |
| series | work；season 挂在 work 下；episode 挂在 season 下 | 一部剧，它的季和集 |

这一点由程序检查。没有视频文件的缺失集同样是一行 `episode`。

`field_sources` 的值是来源 id，手动修改记为 `manual`。手动修改一个字段时，同时把它写进 `locked_fields`。再刮削时，`locked_fields` 里的字段保持原值，各来源的原始结果照常更新。

## 外部编号和原始结果

```sql
create table item_external_ids (
  item_id integer not null references items (id) on delete cascade,
  provider text not null,                  -- tmdb、imdb、tvdb、anidb、bangumi、douban、vndb、ymgal、cngal
  external_id text not null,
  is_primary integer not null default 0,
  primary key (item_id, provider)
);

create index ix_item_external_ids_lookup on item_external_ids (provider, external_id);

create table item_source_records (
  item_id integer not null references items (id) on delete cascade,
  source text not null,                    -- tmdb、douban、fanarttv，或插件 id
  fetched_at text not null,
  raw text not null,                       -- 该来源返回的原始 JSON
  primary key (item_id, source)
);
```

刮削前先查 `item_source_records`：已经有记录的来源不再请求，只补缺的。强制刮削才覆盖已有记录。

## 人物

各类型共用。同一位声优在 Galgame 和动漫里是同一行 `people`。

```sql
create table people (
  id integer primary key,
  name text not null,
  original_name text,
  photo_path text,
  created_at text not null,
  updated_at text not null
);

create table person_external_ids (
  person_id integer not null references people (id) on delete cascade,
  provider text not null,
  external_id text not null,
  primary key (person_id, provider)
);

create table item_people (
  item_id integer not null references items (id) on delete cascade,
  person_id integer not null references people (id),
  role text not null,                      -- director、actor、writer、producer、voice
  character_name text,                     -- 饰演或配音的角色
  position integer not null,
  primary key (item_id, person_id, role)
);

create index ix_item_people_person on item_people (person_id, role);
```

## 标签

`tag_kind` 就是类型声明里的 `tag_kind`。电影和电视剧的「剧情」是同一行。

```sql
create table tags (
  id integer primary key,
  tag_kind text not null,                  -- genre、studio、country、brand、platform
  name text not null,
  unique (tag_kind, name)
);

create table item_tags (
  item_id integer not null references items (id) on delete cascade,
  tag_id integer not null references tags (id),
  position integer not null,
  primary key (item_id, tag_id)
);

create index ix_item_tags_tag on item_tags (tag_id);
```

## 图片和评分

主海报放在 `items.poster_path`，海报墙直接读；季海报就是季那一行的 `poster_path`。其余图片放这里，种类对应 TMM 的艺术图类型。`file_path` 指向莫提斯自己数据目录里的文件，按哈希分子目录存放。写到视频旁边的那一份，记在 `media_files`，`file_kind = image`。

```sql
create table item_images (
  id integer primary key,
  item_id integer not null references items (id) on delete cascade,
  image_kind text not null,                -- fanart、banner、clearlogo、clearart、discart、keyart、thumb、extrafanart
  source text,
  url text,
  file_path text,                          -- 下载后的本地文件
  language text,
  width integer,
  height integer,
  position integer not null
);

create index ix_item_images_item on item_images (item_id, image_kind, position);

create table item_ratings (
  item_id integer not null references items (id) on delete cascade,
  source text not null,                    -- imdb、tmdb、douban、tomatometerallcritics
  rating real not null,
  max_rating real not null,                -- 10 或 100
  vote_count integer,
  primary key (item_id, source)
);
```

## 来源顺序

整个类型有一条默认顺序（`field_key` 为空字符串）。某个字段要不同顺序，再单独写行。`is_excluded = 1` 表示这个字段不用该来源。

```sql
create table source_orders (
  data_type_id text not null references data_types (id),
  field_key text not null default '',
  source text not null,
  position integer not null,
  is_excluded integer not null default 0,
  primary key (data_type_id, field_key, source)
);
```

## 本地文件

`item_id` 可以为空：扫到了文件但还没认出是哪部，先入库。视频挂在 `work`（电影）或 `episode` 上。Galgame 不记单个文件，整个游戏目录记一行 `file_kind = game`，`path` 是目录。

```sql
create table media_files (
  id integer primary key,
  library_id integer not null references libraries (id),
  item_id integer references items (id) on delete set null,
  path text not null unique,
  file_kind text not null,                 -- video、subtitle、trailer、nfo、image、game
  size integer,
  duration_seconds integer,
  created_at text not null,
  updated_at text not null,
  check (file_kind in ('video', 'subtitle', 'trailer', 'nfo', 'image', 'game'))
);

create index ix_media_files_item on media_files (item_id);
```

## 任务

整理、刮削、重命名、清理旧文件、下载图片、写 NFO 都进任务队列。定时扫描和连载剧的定时刷新写在 `schedules`，到点生成任务。

```sql
create table tasks (
  id integer primary key,
  task_type text not null,                 -- organize、scrape、scrape_library、rename、cleanup、download_images、write_nfo
  status text not null,                    -- queued、running、succeeded、failed、cancelled
  priority integer not null default 0,     -- 大的先跑；后续任务默认 -1
  parent_task_id integer references tasks (id) on delete cascade,
  root_task_id integer,                    -- 根任务为空；子孙都指向同一个根
  payload text,                            -- JSON
  result text,                             -- JSON
  error text,
  created_at text not null,
  started_at text,
  finished_at text
);

create index ix_tasks_status on tasks (status, created_at);
create index ix_tasks_parent on tasks (parent_task_id);
create index ix_tasks_root on tasks (root_task_id);

create table schedules (
  id integer primary key,
  name text not null,                      -- 每晚扫描电影库
  cron text not null,                      -- 0 3 * * *
  task_type text not null,
  payload text,                            -- JSON，如 {"library_id":1}
  is_enabled integer not null default 1,
  last_run_at text,
  next_run_at text
);
```

一个任务跑完可以生成后续任务，例如整理完给每部新认出的电影各生成一个刮削任务。标记完成和插入后续任务在同一个事务里。任务列表只列根任务；每个任务显示直接子任务的个数和状态，逐层展开；是否还在跑按整棵树算。程序启动时，上次没跑完的 `running` 记为失败。

## 例子：《教父》

`items` 里两行：

| id | parent_id | kind | title | original_title | release_date | fields | field_sources | locked_fields |
|---|---|---|---|---|---|---|---|---|
| 1 | 空 | collection | 教父（系列） | The Godfather Collection | 空 | `{}` | `{"title":"tmdb"}` | `[]` |
| 2 | 1 | work | 教父 | The Godfather | 1972-03-14 | `{"runtime":175,"certification":"R"}` | `{"title":"manual","overview":"douban","runtime":"tmdb"}` | `["title"]` |

其余表里与第 2 行相关的：

- `item_external_ids`：`tmdb = 238`（主编号），`imdb = tt0068646`。
- `item_source_records`：`tmdb` 一行，`douban` 一行，各自存原始 JSON。
- `item_people`：科波拉 `director`；马龙·白兰度 `actor`，饰维托·柯里昂；阿尔·帕西诺 `actor`，饰迈克尔·柯里昂。
- `item_tags`：`genre` 犯罪、`genre` 剧情、`studio` 派拉蒙。
- `item_ratings`：`imdb`、`tomatometerallcritics`。
- `media_files`：`M:\plex\movie\The.Godfather.1972…` 下的视频文件。

海报墙只读 `title`、`subtitle`、`poster_path`、`release_date`。打开详情页时，才按 `type_fields` 把 `fields` 里的 `runtime` 显示成「时长：175 分钟」。

## 例子：插件新增 Galgame

插件写入 `data_types` 一行：`galgame`，结构 `item`，`subtitle_field = brands`。再写入这些 `type_fields`：

| field_key | label | value_type | stored_in | 对应 |
|---|---|---|---|---|
| title | 游戏名 | text | items_column | `title` |
| original_title | 原名 | text | items_column | `original_title` |
| overview | 简介 | longtext | items_column | `overview` |
| release_date | 发售日 | date | items_column | `release_date` |
| poster | 封面 | images | items_column | `poster_path` |
| fanart | 背景图 | images | images | `image_kind = fanart` |
| brands | 品牌 | tags | tags | `tag_kind = brand` |
| tags | 标签 | tags | tags | `tag_kind = galgame_tag` |
| voice_actors | 声优 | people | people | `person_role = voice` |
| scenario | 剧本 | people | people | `person_role = writer` |
| artists | 原画 | people | people | `person_role = artist` |
| engine | 引擎 | text | fields | 无 |
| play_time | 游玩时长（小时） | number | fields | 无 |
| ratings | 评分 | rating | ratings | 无 |
| website | 官网 | url | fields | 无 |

再写入默认来源顺序：整体 bangumi、ymgal、vndb、cngal；`engine`、`play_time` 只用 vndb；`ratings` 用 bangumi、vndb；`poster` 用 vndb、bangumi、ymgal、cngal；`tags` 用 bangumi、vndb。用户改过的顺序，重新安装时不覆盖。

一款游戏就是 `items` 里的一行 `kind = work`，用的还是上面这些表。外部编号记在 `item_external_ids`，provider 是 bangumi、vndb、ymgal、cngal，第一个认出它的来源是主编号。
