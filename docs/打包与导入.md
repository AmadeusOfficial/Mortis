# 打包与导入

本文写怎么把插件打成 zip、zip 要满足什么、导入时宿主按什么顺序检查、覆盖升级和卸载的规则。

> **先看安全提示。** 导入的插件是在本机运行的 Python 代码，和莫提斯在同一个进程里运行，**没有沙箱**。导入时的 `check_imports` 只是约定检查，用来挡住误用，很容易被绕开，不是安全检查。**只导入你信任的插件。**
>
> `plugin.toml` 里的 `[mortis]` 标记只用来识别「这是不是莫提斯的插件包」，防止拿错文件，**不是认证**，也不代表这个插件被谁审核过。

## 打包

用仓库里的 `scripts/pack_plugin.py`：

```powershell
python scripts/pack_plugin.py <插件目录> -o dist
```

`-o` 可以是输出目录（默认 `./dist`，文件名是 `<插件 id>-<版本>.zip`），也可以直接写以 `.zip` 结尾的文件名。

它做的事：

1. 检查目录里有 `plugin.toml` 和 `__init__.py`。
2. 解析清单：`[mortis]`、`api_version`、`min_mortis_version`、id 格式、`[[sources]]`/`[[players]]`/`[[hooks]]`，并要求包 id 带命名空间。
3. 做 import 约定检查（跳过 `tests/` 和 `test_*.py`）。
4. 打成 zip：只放需要的文件，**不放** `tests/` 目录、`test_*.py`、`__pycache__`、`.pyc` 和以点开头的文件或目录。文件按路径排序、时间戳固定，内容不变时每次打出的 zip 完全一样。
5. 用导入时同一套规则做静态检查（路径、文件类型、各项限额）。
6. 在临时目录里按导入流程装一遍，确认清单和 `PLUGIN` 对象逐项对得上。**这一步会执行你自己插件的代码**。
7. 输出 zip 路径、**包哈希**（和导入预览里显示的是同一个值）和 zip 文件的 SHA-256。

任何一步不通过，脚本用中文说明原因并以非零状态退出，不会留下 zip。

脚本依赖莫提斯的代码（它复用了宿主的清单解析和检查），所以要在能 `import mortis` 的环境里跑，比如在仓库里 `pip install -e ".[dev]"` 之后。你也可以自己用任何工具打 zip，只要满足下面的结构和限制，但建议至少用这个脚本检查一遍。

## zip 的结构

两种都可以：

```
plugin.toml          ← 直接放在根目录
__init__.py
sources/...
```

```
my_plugin/           ← 或者只有一个顶层文件夹
  plugin.toml
  __init__.py
```

`plugin.toml` 要在根目录，或者在唯一的顶层文件夹里。其他结构会被拒绝。以 `__MACOSX`、`.DS_Store`、`Thumbs.db` 命名的条目会被忽略。

## 文件类型白名单

只接受下面这些：

- `plugin.toml`（只有这一个 `.toml` 文件）；
- `.py`、`.json`、`.md`、`.txt`；
- 常见图片：`.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.ico`。

出现可执行文件和二进制会被直接拒绝并点名：`.exe`、`.dll`、`.pyd`、`.so`、`.dylib`、`.bat`、`.cmd`、`.com`、`.msi`、`.scr`、`.ps1`、`.vbs`、`.js`、`.jar`、`.sh`、`.lnk`，以及嵌套的压缩包（`.zip`、`.7z`、`.rar`、`.gz`、`.tar`、`.whl`）。白名单以外的其他后缀也会被拒绝。需要第三方包的插件不能导入，插件只能用标准库、Pydantic 和 `mortis.plugin_api`。

## 限额

| 项目 | 上限 |
|---|---|
| 压缩包大小 | 20 MB |
| 单个文件解压后 | 5 MB |
| 全部文件解压后合计 | 30 MB |
| 文件数 | 500 个 |
| 条目路径长度 | 200 个字符 |
| 目录层级 | 8 层 |
| 压缩比 | 100 倍（单个文件解压后超过 64 KB 才检查；整包再检查一次） |
| 确认令牌有效期 | 10 分钟 |
| 同时等待确认的预览 | 8 个，超出时最早的作废 |

解压时逐块读，按实际读到的字节数计算，不信 zip 头里声明的大小。

## 路径和条目的规则

每个条目都要通过下面的检查，任何一条不满足，整个包被拒绝：

- 反斜杠按斜杠处理；
- 不能有空段、`.`、`..`，不能是绝对路径或网络路径，不能有盘符，**不能含任何冒号**（包括 NTFS 备用数据流），不能含控制字符；
- 每一段去掉末尾的点和空格、不分大小写之后再检查；
- 不能用 Windows 保留设备名：`CON`、`PRN`、`AUX`、`NUL`、`COM1` 到 `COM9`、`LPT1` 到 `LPT9`（`CON.txt` 也不行）；
- 按规范化后的路径检查重复和大小写冲突，文件和目录不能同名；
- 只接受普通文件和目录，**拒绝符号链接**、重解析点、加密条目，压缩方式只支持存储和 deflate。

## 校验顺序

导入分两步：先静态检查并预览，用户确认之后才试运行。**预览阶段不执行插件的任何代码。**

第一步，上传 zip 后的静态检查：

1. 流式接收到临时文件，超过大小上限立刻中断，不把整个文件读进内存。
2. 确认是有效的 zip，逐条检查类型、路径、重复和冲突、文件类型白名单、文件数，并确定包根目录。
3. 解压到私有临时目录，同时检查单文件大小、总大小和压缩比，计算每个文件的 SHA-256。
4. 只读 `plugin.toml`，不执行代码：
   - 没有 `[mortis]` 表：拒绝，提示「这不是莫提斯插件包」；
   - `api_version` 或 `min_mortis_version` 不满足：提示升级莫提斯，或者插件太旧；
   - 包 id 格式不对、不带命名空间（`作者.名字`）、用了保留的命名空间（`mortis`、`builtin`）或 Windows 保留设备名：拒绝；
   - 包 id 和内置插件重名，或包里的 id（包、来源、播放、钩子）和别的插件重名：拒绝。
5. 生成预览和一个一次性的确认令牌。

预览会显示：插件名称和版本、接口版本、提供的能力、订阅的事件和声明的权限、规范化后的文件清单（大小和逐文件 SHA-256）、包哈希；同 id 已安装时还会显示新旧对比（新增、删除、改动的文件）。

第二步，用户确认：

1. 设置页会弹出安全提示，要求勾选「我信任这个插件」后才能继续（接口也要求带上这个确认）。
2. 令牌一次性：取出就作废，不管后面成不成功；过期或无效要重新上传。
3. 再次核对：目标目录在预览之后没变，暂存的文件没被改动，否则要求重新上传。
4. **试运行**：做 `check_imports`，再真的 import 一遍，并检查清单和 `PLUGIN` 对象逐项一致。这一步已经在执行插件代码了，它不是安全检查，所以要先让用户确认。
5. 替换目录并生效，见下。

## 全新安装和覆盖升级

- **全新安装**：直接热加载，不用重启。装好后重新加载失败的话会撤回。
- **覆盖升级**（同 id 的插件在数据目录里已经有了）：新文件替换旧文件，**需要重启莫提斯才完全生效**，因为旧版本的对象还留在内存里清不干净。导入完成后设置页会提示需要重启。
- 导入不比较版本号，旧版也能覆盖新版。
- 内置插件不能被覆盖：包 id 和内置插件重名会被拒绝。
- 替换目录的做法：先把旧目录改名成 `.old`，再把新目录改成正式名，任何一步失败都把旧目录改回去，不会留下装了一半的插件。

## 手动放进插件目录

也可以不打包，直接把插件文件夹放进数据目录下的 `plugins/`，在设置页「插件管理」里点「重新加载插件」。手动放的插件同样要有 `[mortis]` 清单，没有的显示为加载失败。这种方式不经过上面的静态检查，加载时就会 import 代码，只放你信任的插件。

## 卸载

在设置页「插件管理」里卸载。

- 只能卸载数据目录里的插件，内置插件不能卸载，只能停用。
- 包带的来源、播放、钩子不能单独卸载，要卸载整个包。
- 卸载会重新加载插件，这个插件提供的东西立刻不可用。
- **数据保留**：该插件自己的数据目录（钩子的 `data_dir`）、设置和密钥保留，重新装回来可以接着用。它写在条目上的标签也留在库里，卸载后不会被撤掉，需要的话由用户手动删除。
