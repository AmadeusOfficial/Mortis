# 插件规范

本文是宿主和插件之间的约定，供查阅。第一次写插件请先看《插件开发指南》；事件和钩子的运行细节见《事件参考》；zip 的结构、限额和导入流程见《打包与导入》。

接口的逐个类型、字段和方法写在 `src/mortis/plugin_api/` 的注释里（从 `mortis.plugin_api` 引用）。本文没写的接口就是还没有，不要照着猜。

## 边界

插件是本机目录里的一段 Python 代码，和宿主在同一个进程里运行，**没有进程隔离，也没有沙箱**。插件只能 import 三样东西：Python 标准库、Pydantic、`mortis.plugin_api`。

插件不能做的事：

- 建表、写数据库迁移、直接读写数据库。表归宿主，字段按数据类型的目录存成文档；要改数据，只能经宿主给的服务接口（目前只有事件钩子里的标签读写）。
- 带页面、注册路由、往浏览器输出内容。设置页由宿主按插件声明的设置模型生成。
- 自带第三方包或原生扩展。
- 自己联网、自己开进程。联网走宿主的客户端，开程序走宿主的 `launch` 或 `open_default`。
- 转码，或者往浏览器写视频字节。

## 能力组合

一个插件包可以提供下面四种东西，想带几样带几样，不再分互斥的种类：

| 能力 | 做什么 | 代码里的对象 | 清单里的表 |
|---|---|---|---|
| 数据类型 | 在三种结构里选一种，提交一份字段目录（`DataTypeSpec`），并给出默认的来源顺序 | `DataTypePlugin` | 无 |
| 来源 | 只给某一种数据类型填字段。服务的类型可以是内置的电影、电视剧、动漫，也可以是另一个插件的类型 | `SourcePlugin` | `[[sources]]` |
| 播放 | 用本机播放器打开一个本地文件，或者启动游戏文件夹里的程序 | `PlayerPlugin` | `[[players]]` |
| 事件钩子 | 订阅宿主发布的事件，在后台做点事（目前能读条目、增删自己名下的标签、联网） | `HookPlugin` | `[[hooks]]` |

比如 Galgame 插件带着数据类型、Bangumi、VNDB、月幕、CnGal 四个来源和一个「Galgame 启动」播放；示例里的 `tag_rules` 带一个来源和一个钩子。只有给别人的类型补来源时，才需要单独发布一个只含来源的包。

数据类型插件只能选择已有的结构并提交字段目录，不自带页面，也不建表。结构只有三种：`item`（单条目）、`item_group`（单条目加分组，比如系列电影）、`series`（作品、季、集）。`plugin.toml` 里不再有 `kind`，旧文件里写了会被忽略。

## 目录

插件目录有两个：程序自带的 `plugins/`，和数据目录下的 `plugins/`。一个插件一个文件夹，文件夹名以 `.` 或 `_` 开头的会被跳过。文件夹名随便起，插件的身份以 `plugin.toml` 里的 `id` 为准（从 zip 导入时，文件夹名会取 `id`）。

```
plugins/galgame/
  plugin.toml
  __init__.py        定义 PLUGIN
  sources/
    __init__.py
    bangumi.py
    vndb.py
```

包内的其他模块用相对导入（`from .sources.vndb import VndbSource`）。

## plugin.toml

```toml
id = "author.my_plugin"
name = "我的插件"
version = "0.1.0"

[mortis]
api_version = 1
min_mortis_version = "0.2.0"

[[sources]]
id = "author.my_source"
name = "我的来源"
data_type = "movie"

[[players]]
id = "author.my_player"
name = "我的播放"

[[hooks]]
id = "author.my_hook"
event = "scrape.finished"
data_types = ["movie"]
writes = ["tags:keyword"]
```

顶层：

- `id`、`name`、`version` 必填。`version` 是显示用的文本，宿主不比较版本高低，导入时同 id 的包不管版本新旧都能覆盖。
- `id` 的格式见下面的「id 和命名空间」。

`[mortis]` 表必填：

- `api_version`：整数，表示插件依赖的接口版本。只在有破坏性改动时才加一。没有这个表的 `plugin.toml` 不是莫提斯插件，会被拒绝加载（手动放进插件目录的也一样）。
- `min_mortis_version`：可选，字符串，依赖的最低莫提斯版本，比如 `"0.2.0"`。宿主按点分的数字比较（`0.2.0-beta` 取前面的数字部分）。从源码目录直接运行时版本号是 `0.0.0`，这时不拿它挡插件。

版本规则：

- 宿主有一个自己支持的 `api_version` 范围（本版只支持 `1`）。插件的 `api_version` 比范围大，提示「请升级莫提斯」；比范围小，提示「插件太旧，请换新版插件」。
- `min_mortis_version` 比当前宿主高，提示升级莫提斯。
- 事件对象和 `plugin_api` 里的模型会向后兼容地增加字段（新字段都有默认值，事件忽略多余字段），这类增加不算破坏性改动，不会提高 `api_version`。

`[[sources]]`、`[[players]]`：

- 每项写 `id` 和 `name`，必填。`[[sources]]` 还可以写 `data_type`，写了设置页不用 import 代码就知道这个来源服务哪个类型；写了就必须和代码里的 `data_type` 一致。`[[players]]` 不能写 `data_type`。

`[[hooks]]`：

- `id`：钩子 id。
- `event`：订阅的事件名，必须是《事件参考》里列出的事件，不存在的事件在加载时报错。**一个钩子对象订阅一个事件**；要订阅几个事件，就写几个钩子。
- `data_types`：可选，字符串列表，限定数据类型。不写或写空表示不限；写了名单，只有数据类型在名单里的事件才会投递，没有数据类型的事件（比如不属于任何条目的 `task.failed`）也不投递。名单里写了不存在的类型不会报错，只是永远收不到。
- `writes`：可选，字符串列表，声明要写什么。目前只有标签：`tags:<标签类别>`，类别用小写字母、数字和下划线、字母开头，比如 `tags:keyword`。不认识的写法在加载时报错；没声明的写入在运行时被拒绝。

### 清单和代码逐项一致

`[[sources]]`、`[[players]]`、`[[hooks]]` 的 `id` 必须和 `PLUGIN` 里的对象按 id 一一对上，**多了、少了都会报错**，错误信息会指出差了哪几个。包停用或加载失败时宿主不 import 代码，就是靠这份名单把子项列在设置页上的。

## PLUGIN 对象

`__init__.py` 里定义 `PLUGIN`，有四种写法：

```python
PLUGIN = MySource()                       # 单个来源的简写
PLUGIN = MyPlayer()                       # 单个播放的简写
PLUGIN = DataTypePlugin(spec=..., sources=(...), players=(...))   # 数据类型，可带它专用的来源和播放
PLUGIN = Plugin(sources=(...), players=(...), hooks=(...), data_type=...)   # 任意组合
```

- 单个对象的简写：对象的 `id` 就是 `plugin.toml` 的 `id`，`plugin.toml` 里**不能**再写 `[[sources]]`、`[[players]]`、`[[hooks]]`。
- 钩子没有简写，要用 `Plugin(hooks=(...))`。想让数据类型插件也带钩子，写成 `Plugin(data_type=DataTypePlugin(...), hooks=(...))`。
- `DataTypePlugin.sources` 和 `Plugin.sources` 同时有时会合并；`DataTypePlugin` 自带的来源，`data_type` 必须等于它的 `spec.id`。
- 不管用哪种写法，注册表内部都按「包信息加具名扩展项」处理，行为一致。

## id 和命名空间

插件 id、来源 id、播放 id、钩子 id 的格式都是 `名字` 或 `作者.名字`：只能有一个点，每一段只用小写字母、数字和下划线，并以字母开头。

- **不带点的 id 留给程序自带的插件。** 从 zip 导入的插件，包 id 必须带命名空间（`作者.名字`）。手动放进数据目录的插件加载器不强制，但请照样用命名空间，不然以后撞名没有办法。
- **保留的命名空间**：`mortis.*`、`builtin.*` 留给宿主，插件不能使用。
- 包里的子来源、子播放、钩子的 id 也在同一个 id 空间里，同样建议带命名空间。
- 整个注册表里 id 不能重名：包内各项之间、插件之间、来源之间、插件和来源之间都不行。数据类型的 id（`spec.id`）不能和内置类型同名，子来源和子播放也不能和它同名。

## 身份：id 定下后不改

id 是库里长期保存的键：

- 来源快照、条目的外部编号、字段的来源顺序都按来源 id 存。
- 设置文件的 `[sources.<id>]`、密钥文件的同名节、OAuth 回调地址也按来源 id 存。
- 钩子写的标签按**包 id** 记来源；熔断后的停用记录按钩子 id 存；钩子的数据目录按包 id 命名。
- 同一个包里的几个钩子，共享这个包名下的标签。

所以 id 定下后就不能改。改了，已有的快照、设置、标签来源和登录都对不上。显示名称可以随时改。

## 覆盖和重名

两个目录里有同 id 的插件时，数据目录的优先，并且按整个插件包覆盖：旧包连同它带的来源、播放、钩子一起换掉，不会只换一半。

发现重名时，先加载的保留，后加载的整个包不生效，宿主不会 import 它：

- 后来的包，id 还没被占用：设置页上列一条错误，写明和谁重名了。
- 后来的包，id 已经被占用（比如数据目录里放的覆盖包又和别的插件重名）：不列出，只记日志，原来的包照常工作。

用 zip 导入时的覆盖规则（同 id 在数据目录里已有、内置插件不能被覆盖、覆盖要重启）见《打包与导入》。

## 启用和停用

停用的插件列在设置文件的 `[plugins] disabled` 里，写的是插件、来源、播放或钩子的 id。

- 停用数据类型插件：它带的来源和播放插件一起停用。它的库只能浏览，不能扫描、刮削和启动，已有的条目保留。
- 停用整个包：它带的钩子不再收到事件。
- 停用某个来源或播放插件：只停这一个。
- 钩子被熔断（连续失败后自动停用）时，它的 id 也会写进这个列表，见《事件参考》。
- 重新启用数据类型插件：它带的来源和播放插件恢复各自原来的开关。
- 插件加载失败：它带的来源都算停用，设置页显示父插件的错误。

设置页可以重新加载插件，不用重启进程。重新加载会让改过的代码生效，插件包里的子模块也会重新执行。

## 标签来源规则

标签按来源记录，各写各的：

- 来源有：`scrape`（刮削）、插件的包 id、手动（用户在界面编辑）。条目上显示的标签是各来源的并集，筛选和写出的 NFO 也用并集。
- **刮削只替换自己名下的标签。** 再次刮削时，刮削来源的标签按新结果更新，插件加的和用户手动加的不受影响。
- **插件只能增删自己名下的标签。** `add_tags` 记在本插件名下；`remove_tags` 只能撤本插件加过的，其他来源的标签返回 `not_owned`。如果同一个标签还有别的来源，撤掉本插件的来源后它仍然显示。
- **用户删除过的标签，插件补不回来。** 用户在界面删掉一个标签，宿主清掉它的所有来源（包括插件的），并记一条「手动删除」；之后插件再 `add_tags` 同一个标签会被忽略（结果在 `removed_by_user` 里），刮削也不再补回。用户自己再加回去，这条记号就清掉了。
- **锁定的字段不写。** 标签属于某个被锁定的字段时，刮削和插件的写入整批跳过（结果在 `locked` 里）。锁定按字段键判断：标签类别对应某个 `tags` 字段时才受锁定管；没有对应字段的类别无法被锁定。
- 排序：刮削的标签排在前面，插件的跟在后面；刮削重排不会打乱插件标签之间的顺序。
- 写完后，已经整理过（写过 NFO）的条目会静默重写 NFO，并且只在确实有新增或撤销时才写。

用法和幂等写法见《事件参考》。

## 权限声明 writes

钩子要写数据，必须在 `[[hooks]]` 的 `writes` 里声明。目前只有 `tags:<标签类别>`。

- 声明之外的写入，运行时抛 `HookPermissionError`。
- 声明的格式不对，加载时报错，整个包不生效。
- 设置页和导入预览会把每个插件声明的权限列出来，让用户知道它要写什么。

宿主不开放其他写操作：没有改字段值、改文件、改设置的接口。

## 预留的过滤点

宿主以后可能允许插件对刮削过程里的数据做改写（比如标题清洗、候选打分、图片排序这类「过滤点」）。**本版没有这些接口**，清单和事件里也没有对应的写法，不要照着猜。是否做、做成什么形状，由以后的 `api_version` 决定；到时会通过 `api_version` 区分，现有插件不受影响。

## import 检查

加载前宿主会检查插件里的每个 `.py` 文件（`tests/` 目录和 `test_*.py` 不检查，也不随插件加载），下面这些写法会被拒绝加载：

- 标准库、Pydantic、`mortis.plugin_api` 以外的包；`mortis` 的其他模块，包括 `mortis.plugin_api` 的子模块（需要的类型都能直接从 `mortis.plugin_api` 引用；`mortis.plugin_api.testing` 只能用在测试里）。
- 能开进程或绕开宿主联网的模块：`subprocess`、`multiprocessing`、`_winapi`、`_posixsubprocess`、`ctypes`、`importlib`、`socket`、`ssl`、`http`、`urllib.request`、`ftplib`、`smtplib`。
- 直接调用 `__import__`、`eval`、`exec`、`compile`。
- `os.system`、`os.popen`、`os.startfile`、`os.fork`、`os.spawn*`、`os.exec*`、`os.posix_spawn*` 这类调用。

相对导入（包内模块之间）不受限制。

**这只是约定检查，用来挡住误用，不是安全沙箱。** 它很容易被绕开。插件和宿主同进程运行，能做宿主能做的事，所以只导入、只运行你信任的插件。

## 来源插件

来源插件要实现三个方法：

- `search(host, title)`：返回 `Hit` 列表。宿主用标题、原名、别名和年份算匹配度，自己决定用哪一条。
- `fetch(host, external_id)`：返回这一条的完整原始结果。宿主把它整份存成快照。
- `candidates(raw)`：从快照算出 `{字段键: 值}`。值的格式按字段的值类型，见 `plugin_api` 开头的说明。这个方法不能联网，因为再次刮削时宿主只对已有快照调用它。

其他约定：

- 网络请求只用 `host.get_json`、`host.post_json`、`host.get_text`。宿主负责代理、证书、限速（插件用 `requests_per_second` 声明）和任务记录。
- 失败就抛 `SourceError`，消息写给用户看，不带令牌和完整地址。令牌被拒绝时抛 `SourceAuthError`。找不到这一条时也抛 `SourceError`。不要吞掉异常后返回空结果：任务看起来成功了，其实什么都没拿到。
- 只填自己所服务类型的字段，字段键必须是那个类型的字段目录里有的。
- 设置用 `Settings`（Pydantic 模型）声明，存在 `[sources.<id>]`；密钥用 `Secrets` 声明，存在密钥文件的同名节。设置页自动生成表单，密钥不回显。表单支持的写法见下面的「设置表单」。
- 没填好密钥、来源用不了时，`enabled` 返回 False，宿主就跳过这个来源；`disabled_reason` 返回设置页上显示的提示。
- 需要用户登录的来源声明 `oauth`。跳转、回调、存令牌、到期前续期都由宿主做，插件用 `host.access_token()` 取令牌，用 `account` 返回当前账号。
- 公共凭据只用官方文档里公开的那份，写进 `Settings` 的默认值。私人密钥不进仓库，也不要放进发布的插件包。

## 数据类型插件

- `spec`：字段目录。值类型、存储位置、属于哪一层、在详情页哪个分区、能否锁定、能否筛选和排序，都在 `FieldSpec` 里声明，完整说明见 `plugin_api` 开头。不能和内置类型同 id，字段目录要通过宿主校验，不合格会在加载时列出全部问题。
- `default_orders`：默认来源顺序。键是 `""`（对整个类型）或某个字段键，值是来源 id 的列表。宿主只给还没有顺序的字段补上默认值，用户改过的顺序在重新加载后保留。
- `sources`：这个类型自带的来源。每个来源的 `data_type` 必须等于 `spec.id`。
- `players`：这个类型自带的播放插件。
- 类型自己的设置（匹配阈值、要跳过的文件夹）存在 `[types.<id>]`，由宿主提供。
- 扫描方式目前只有 `folder`：一个文件夹算一个条目。
- 值类型只有这几种：text、longtext、number、date、rating、people、tags、images、url。

## 播放插件

- 实现 `play(host, path)`。宿主已经确认文件存在；打不开就抛 `PlayerError`。
- 不自己开进程，只调 `host.launch(程序, 参数列表)` 或 `host.open_default(路径)`。宿主不经过 shell，启动后不等播放器结束。
- 用不了时（比如没装这个播放器），`unavailable_reason` 返回原因；`detected_path` 返回实际会启动的程序路径，显示在设置页上。启动游戏的插件可以返回 None。
- 播放插件用 `file_kinds` 声明能打开哪种本地文件，默认是视频。打开游戏文件夹（`game`）的播放插件还要给出文件夹里可以启动的程序候选；只有一个就直接启动（用户要求重选时也交给页面确认），多个时宿主把候选交给页面选，选过的记在这个播放插件的设置里，下次直接用。
- 启动游戏的播放插件要在 `Settings` 里声明 `executables: dict[str, str]`，宿主用它记住选择，设置页不显示。
- 宿主允许启动游戏文件夹里任意 `.exe`，不限于插件给的候选。
- 程序自带的播放插件只有「系统默认播放器」。设置文件的 `[playback] player` 指定用哪个播放插件，留空就用第一个能播放视频的。
- 网页内播放不在当前接口里，插件只负责用本机播放器打开文件或启动游戏。

## 事件钩子

钩子是发布订阅：只订阅事件，宿主在库提交成功之后发布，处理函数不能中断或改写宿主的流程。事件清单、字段、限额、熔断、防循环和写法，全部在《事件参考》里。这里只列接口：

- `HookPlugin.on_event(host, event)`：两个槽位固定不变，以后新增的上下文挂在 `host` 或 `event` 的属性上。
- `HookHost`：读条目 `get_item`；增删自己名下的标签 `add_tags`、`remove_tags`；联网 `get_json`、`post_json`；自己的数据目录 `data_dir`；日志 `log`。没有直接写库、改字段、写 NFO 的接口。

## 设置表单

`Settings` 和 `Secrets`（Pydantic 模型）的 JSON Schema 只支持下面这个子集，其余写法按文本框处理，界面不会渲染嵌套内容：

- `type: boolean`：开关；`type: integer` 或 `number`：数字框；`type: string`：文本框。
- `format: "file-path"`：带文件选择的路径框，字符串字段用 `json_schema_extra={"format": "file-path"}` 写。
- `title` 当标签，`description` 当提示，`default` 当初始值。
- `Secrets` 里的字段一律按密码框显示，只存字符串，不回显。
- 不支持嵌套对象、数组、`enum`、`oneOf`。字段尽量用简单类型加默认值。

只有来源插件的 `Settings`、`Secrets` 和播放插件的 `Settings` 有设置表单；钩子目前没有设置和密钥入口。

## 测试

- `mortis.plugin_api.testing` 提供假宿主：`FakeHost`（来源）、`FakePlayerHost`（播放）、`FakeHookHost`（钩子），不连网、不启动程序，只记下插件做了什么。只在测试里用，插件代码里不要 import 它。
- 每个来源用假 Host，把录下来的响应交给插件，覆盖搜索、详情和候选值。测试不连真站。
- 录下来的响应放在测试夹具目录里，只保留用得到的部分，去掉令牌和个人信息。
- 钩子用 `FakeHookHost` 测：它按真宿主的规则处理写权限、锁定字段、只能撤自己加的标签、用户删除过的标签补不回来，以及每次事件的额度。一个实例对应一次事件。
- 数据类型插件要测：注册表能加载它，字段目录通过校验，默认来源顺序写进了库，停用后它的来源一起停。
- 作者自己的测试放在插件目录的 `tests/` 里（或命名为 `test_*.py`）：加载时不检查、不加载，打包时不放进 zip。
- 用任意工具压缩成 zip 即可；想在发布前按导入规则自检，可以用 `scripts/pack_plugin.py`，见《打包与导入》。
