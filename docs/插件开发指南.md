# 插件开发指南

写莫提斯插件不需要莫提斯的源码，也不需要安装任何东西：一个文件夹、两个文件，放进莫提斯的插件目录就能跑，压缩成 zip 就能发给别人。本文从一个最小的播放插件开始，走完写、试、打包、导入，再讲来源、事件钩子和插件设置。需要查细节时看后面几份文档：

- 《插件规范》：清单、id、版本、标签规则等所有约定，供查阅。
- 《事件参考》：事件钩子什么时候触发、带什么、有哪些限制。
- 《打包与导入》：zip 的结构、限额、校验顺序、覆盖和卸载。

> **安全提示：** 插件是在本机运行的 Python 代码，和莫提斯同一个进程，没有沙箱。莫提斯的检查只是约定检查，不是安全检查。写插件时请遵守约定，导入别人的插件时只导入你信任的。

## 能写什么

一个插件包可以带下面几样东西，想带几样带几样：

- **来源**：从某个站点取元数据，给某一种数据类型（电影、电视剧、动漫，或别的插件的类型）填字段。
- **播放**：用本机播放器打开文件，或启动游戏文件夹里的程序。
- **事件钩子**：订阅「刮削完成」这类事件，在后台做点事，比如按规则给条目补标签。
- **数据类型**：提交一份字段目录，让莫提斯多管一种东西。

插件不能自带页面、不能建表、不能自己联网或开进程（要经宿主）。详见《插件规范》的「边界」。要让用户改设置，声明一个 Pydantic 模型，设置页由宿主按它生成，见「7. 给插件加设置」。

## 你需要什么

- 一份能运行的莫提斯（发布包解压即可）。
- 一个文本编辑器。

插件代码只能 import 三样东西：Python 标准库、`pydantic`、`mortis.plugin_api`。它们都由莫提斯在运行时提供，插件不能带第三方包。`mortis.plugin_api` 你本机不用装，写代码时对着接口源码看：[`src/mortis/plugin_api/`](https://github.com/AmadeusOfficial/Mortis/tree/main/src/mortis/plugin_api)。每个类、每个方法的约定都写在那里的注释里，比本文更全。

想要编辑器补全、写自动测试或在发布前自检，见文末「可选：补全、测试和自检」。

## 1. 第一个插件：用系统默认程序播放

新建一个文件夹，名字随意，建议和 id 一样：

```
zhangsan.osplay/
  plugin.toml
  __init__.py
```

`plugin.toml`：

```toml
id = "zhangsan.osplay"
name = "本机播放器"
version = "0.1.0"

[mortis]
api_version = 1
```

`__init__.py`：

```python
from mortis.plugin_api import PlayerHost, PlayerPlugin


class OsPlayer(PlayerPlugin):
    id = "zhangsan.osplay"          # 和 plugin.toml 的 id 一样
    name = "本机播放器"

    def play(self, host: PlayerHost, path: str) -> None:
        host.open_default(path)     # 宿主替你打开，不用自己 import subprocess


PLUGIN = OsPlayer()
```

要点：

- **id 写成 `作者.名字`**：小写字母、数字和下划线，一个点，字母开头。`mortis.*` 和 `builtin.*` 保留给宿主。**id 一旦有人用过就不能改**：设置、快照、标签来源都按它存。名称和版本随时可以改。
- **`[mortis]` 表必须有**，`api_version` 现在写 `1`。没有这张表，莫提斯不认为它是插件。
- **模块里必须有 `PLUGIN`。** 单个对象的简写 `PLUGIN = OsPlayer()` 要求对象的 `id` 等于清单的 `id`。想在一个包里带多样东西，见第 5 步。
- 开进程、联网都经宿主：播放用 `host.launch` 或 `host.open_default`，来源用 `host.get_json` 等。直接 import `subprocess`、`socket`、`urllib.request` 会加载失败。

## 2. 放进插件目录试运行

1. 找到莫提斯的数据目录。发布包默认在解压目录下的 `data\`；解压目录不能写（比如放进了 Program Files）时在 `%LOCALAPPDATA%\Mortis\`。在托盘设置文件 `desktop.env` 里用 `MORTIS_DATA_DIR` 改过的，以你改的为准。
2. 把整个 `zhangsan.osplay` 文件夹放进数据目录下的 `plugins\`（没有就新建）。
3. 打开 设置 → 插件管理，点「重新加载插件」。插件出现在列表里就是加载成功；加载失败时列表里会写明原因。
4. 到 设置 → 播放，把「默认播放器」选成「本机播放器」，回到详情页点「播放」试一下。

改了代码再点一次「重新加载插件」就生效，不用重启莫提斯。这样放进去的插件不经过 zip 导入的静态检查，加载时直接执行代码。

## 3. 打包成 zip

把插件文件夹压缩成 zip 就行，用资源管理器的「压缩为 ZIP 文件」或 PowerShell：

```powershell
Compress-Archive -Path .\zhangsan.osplay -DestinationPath .\zhangsan.osplay-0.1.0.zip
```

- `plugin.toml` 要在 zip 根目录，或者在唯一的顶层文件夹里（上面这条命令就是后一种）。
- `__pycache__`、`*.pyc`、`.git` 导入时会被跳过，带进去也没关系。
- 其他文件只收 `.py`、`.json`、`.md`、`.txt` 和常见图片。备份文件（如 `.bak`）、可执行文件会让整个包被拒绝，导入时会点名是哪一个，删掉再压缩。

完整规则见《打包与导入》。

## 4. 导入

1. 打开 设置 → 插件管理，点「导入插件（zip）」，选择 zip。
2. 看预览：插件名称、提供的能力、订阅的事件和声明的权限、文件清单和哈希。预览阶段不执行插件的任何代码。
3. 勾选「我信任这个插件」，确认。这时莫提斯才会试运行插件（import 一遍），通不过就不装。
4. 全新安装不用重启；覆盖升级（同 id 已经装过）需要重启莫提斯。

发给别人时把 zip 给他，他照这一步导入。建议在说明里写上插件 id、能力、需要的设置项和会访问的站点，方便对方导入前审查。

## 5. 来源插件

来源插件从某个站点取元数据。最小的来源是一个 `SourcePlugin` 子类加三个方法：

```python
from typing import Any

from mortis.plugin_api import Hit, Host, SourceError, SourcePlugin

API = "https://api.example.com/hello"


class HelloSource(SourcePlugin):
    id = "example.hello_source"
    name = "示例来源"
    data_type = "movie"                  # 服务哪个数据类型
    provider = "example_hello"           # 外部编号的名字

    def search(self, host: Host, title: str) -> list[Hit]:
        data = host.get_json(f"{API}/search", params={"q": title})
        return [Hit(external_id=str(r["id"]), title=r["title"]) for r in data.get("results", [])]

    def fetch(self, host: Host, external_id: str) -> dict[str, Any]:
        data = host.get_json(f"{API}/movies/{external_id}")
        if not isinstance(data, dict) or "title" not in data:
            raise SourceError("示例来源里没有这一条")
        return data                      # 整份存成快照

    def candidates(self, raw: dict[str, Any]) -> dict[str, Any]:
        # 只从快照取值，不联网。键必须是电影字段目录里有的。
        return {"tagline": raw["tagline"]} if raw.get("tagline") else {}


PLUGIN = HelloSource()
```

- **联网只用 `host.get_json`、`host.post_json`、`host.get_text`**。宿主负责代理、限速和任务记录。
- **失败就抛 `SourceError`**，消息写给用户看，不带令牌。不要吞掉异常后返回空结果。
- **`candidates` 不能联网**：再次刮削时宿主只对已有快照调用它。
- 包里有多个 `.py` 时，模块之间用相对导入（`from .parser import parse`）。
- `candidates` 返回值的格式、字段目录的写法，见 [`plugin_api/__init__.py`](https://github.com/AmadeusOfficial/Mortis/blob/main/src/mortis/plugin_api/__init__.py) 开头的注释。

装好后到 设置 → 来源 找到它，需要的话填设置和密钥；在测试库里刮一条，在详情页看各字段的值和来源。

## 6. 来源加钩子：一个包带多样东西

想在一个包里同时带来源和钩子，`PLUGIN` 改用 `Plugin(...)`，并在清单里把每一项列出来：

```toml
id = "example.tag_rules"
name = "示例：按规则补标签"
version = "0.1.0"

[mortis]
api_version = 1

[[sources]]
id = "example.tag_rules_films"
name = "示例片长来源"
data_type = "movie"

[[hooks]]
id = "example.tag_rules_tagger"
event = "scrape.finished"
data_types = ["movie"]
writes = ["tags:keyword"]
```

```python
from mortis.plugin_api import Plugin

from .hook import RuleTagger
from .source import FilmSource

PLUGIN = Plugin(sources=(FilmSource(),), hooks=(RuleTagger(),))
```

清单里的 `[[sources]]`、`[[hooks]]` 要和代码里的对象按 id 一一对上，多了少了都会加载失败。

钩子是一个 `HookPlugin` 子类，实现 `on_event(host, event)`：

```python
from mortis.plugin_api import Event, HookHost, HookPlugin, ScrapeFinished


class RuleTagger(HookPlugin):
    id = "example.tag_rules_tagger"
    name = "示例：按规则补标签"

    def on_event(self, host: HookHost, event: Event) -> None:
        if not isinstance(event, ScrapeFinished):
            return
        item = host.get_item(event.item_id)
        if item is None:
            return
        wanted = wanted_tags(item)               # 按当前字段算出应该有的标签
        if wanted:
            host.add_tags(item.id, "keyword", wanted)   # 已经加过的不会重复写
```

几件要记住的事（细节见《事件参考》）：

- **只能写清单里声明了的权限**：`writes = ["tags:keyword"]` 才能写 `keyword` 类标签。权限要写成 `tags:<类别>`，只写 `tags` 会让整个插件加载失败。
- **只管自己名下的标签**：你加的标签记在你的名下，只能撤自己加的；刮削和用户加的标签你碰不到。用户删除过的标签、被锁定的字段，宿主会拒绝写入并在结果里告诉你，这不是错误。
- **写成幂等的**：同一个条目重新刮削会再触发一次事件，处理多少次结果都要一样。
- **钩子是异步的、有限额的**：每次事件最多联网 5 次、调用标签接口 20 次；连续失败 3 次会被自动停用，设置页「插件管理」的钩子行显示原因，点「重新启用」即可恢复，不用重启（见《事件参考》的「熔断」）；超时只记录不强杀。
- 刮削完成后，任务页里会出现类型为 `hook` 的任务，点开能看到日志；失败的原因也在那里。

完整的例子在仓库的 [`examples/plugins/`](https://github.com/AmadeusOfficial/Mortis/tree/main/examples/plugins)：`hello_source` 是最小的来源插件，`tag_rules` 是来源加钩子的组合插件，规则在设置页配。例子里的站点地址（`api.example.com`）是编出来的，装上之后搜不到东西，只演示写法。

## 7. 给插件加设置

插件不写页面。想让用户能改点什么，就在类上声明一个 Pydantic 模型 `Settings`，设置页按它自动画表单；要填令牌之类的，另声明 `Secrets`。来源插件和钩子两样都能声明，播放插件只有 `Settings`。

下面给上一节的钩子加一组「按标题打标签」的规则：

```python
import re

from pydantic import BaseModel, Field, field_validator

from mortis.plugin_api import Event, HookHost, HookPlugin, ScrapeFinished


class Rule(BaseModel):
    pattern: str = Field(
        title="标题正则",
        description="在标题里查找，找到就加标签",
        json_schema_extra={"ui:placeholder": "例如 ^(异形|Alien)"},
    )
    tag: str = Field(title="标签", min_length=1)
    enabled: bool = Field(True, title="启用")

    @field_validator("pattern")
    @classmethod
    def _compiles(cls, value: str) -> str:
        try:
            re.compile(value)
        except re.error as error:
            raise ValueError(f"不是合法的正则表达式：{error}") from None
        return value


class RuleSettings(BaseModel):
    long_minutes: int = Field(150, ge=1, title="长片下限（分钟）")
    rules: list[Rule] = Field(default_factory=list, title="按标题打标签")


class RuleTagger(HookPlugin):
    id = "example.tag_rules_tagger"
    name = "示例：按规则补标签"
    Settings = RuleSettings

    def on_event(self, host: HookHost, event: Event) -> None:
        if not isinstance(event, ScrapeFinished):
            return
        item = host.get_item(event.item_id)
        if item is None:
            return
        settings = host.settings              # RuleSettings 的实例，已经校验过
        wanted = [
            rule.tag
            for rule in settings.rules
            if rule.enabled and re.search(rule.pattern, item.title, re.IGNORECASE)
        ]
        if wanted:
            host.add_tags(item.id, "keyword", wanted)
```

装上后到 设置 → 插件管理，钩子那一行点「设置」：

- `long_minutes` 是一个数字框，填小于 1 的数会当场提示。
- `rules` 是一个列表，下面有「+ 添加」；每加一条出现「标题正则」「标签」「启用」三项，每条可以删除、上移、下移。
- 点「保存钩子设置」时宿主用 `RuleSettings` 校验，正则写错了会显示出错的位置（如 `rules.0.pattern`）和「不是合法的正则表达式」，不保存。

代码里怎么读：

- **来源、播放插件**：方法收到的 `host` 上有 `host.settings`（来源还有 `host.secrets`），设置页在 设置 → 来源、设置 → 播放。
- **钩子**：`on_event` 收到的 `host` 上有 `host.settings`、`host.secrets`，按钩子 id 存，保存后下一次事件就用新值。
- 拿到的都是校验过的模型实例；用户没保存过时是默认值，所以默认值要能直接用。

几点约定（完整列表见《插件规范》的「设置表单」）：

- 列表、嵌套模型、`Literal` 和 `Enum`（下拉框）、`ge`/`le`/`min_length` 这类约束都能用。
- 字段上的 `json_schema_extra` 可以写 `ui:widget`（`"textarea"` 多行、`"file-path"` 路径框）、`ui:placeholder`、`ui:help`、`ui:order` 给表单提示。
- 模型类的 docstring 会变成说明文字显示在页面上；不想显示就写成注释。
- `Secrets` 只能有字符串字段，一律是密码框，保存后不回显。
- 钩子的 `Settings`、`Secrets` 是后加的。用到它们的插件，`plugin.toml` 的 `[mortis]` 里要写 `min_mortis_version`，填第一个支持钩子设置的莫提斯版本，旧版莫提斯会在加载时提示升级。

测试里不用起莫提斯：`FakeHookHost(hook=RuleTagger, settings={"rules": [{"pattern": "^Alien", "tag": "异形"}]})` 按钩子的 `Settings` 校验这份 dict，不给 `settings` 就是默认值；来源、播放插件的 `FakeHost`、`FakePlayerHost` 用 `settings=` 直接传模型实例。

## 可选：补全、测试和自检

上面的流程不需要装任何东西。如果你想要编辑器补全、写自动测试，或者在发布前用和导入相同的规则检查一遍，可以在自己的插件项目里装一份莫提斯（需要 Python 3.14）：

```powershell
pip install "git+https://github.com/AmadeusOfficial/Mortis@<版本 tag>"
```

装的版本尽量和你实际运行的莫提斯一致。装好后：

- **补全**：编辑器能解析 `mortis.plugin_api`，带类型提示。
- **测试**：用 `mortis.plugin_api.testing` 里的假宿主，不连网，不用起莫提斯：

  ```python
  from mortis.plugin_api.testing import FakeHost

  host = FakeHost(responses={f"{API}/search": {"results": [{"id": 7, "title": "你好电影"}]}})
  hits = PLUGIN.search(host, "你好")
  assert hits[0].external_id == "7"
  assert host.requests[0].params == {"q": "你好"}
  ```

  `FakeHost` 按完整地址（不含查询参数）返回你给的响应，并记下插件发出的每个请求；没登记的地址会让测试失败。播放插件用 `FakePlayerHost`，钩子用 `FakeHookHost`，它们按真宿主的规则处理权限、锁定、所有权和额度。

  测试放在插件目录的 `tests/` 里（或命名为 `test_*.py`）：加载时不检查也不加载，所以测试里可以 `import pytest`。录下来的真实响应只保留用得到的部分，去掉令牌和个人信息。

- **自检和打包**：仓库里的 [`scripts/pack_plugin.py`](https://github.com/AmadeusOfficial/Mortis/blob/main/scripts/pack_plugin.py) 用导入时同一套规则检查清单、import 约定、文件类型和限额，再在临时目录里装一遍，通过后打出 zip，并输出和导入预览一致的包哈希。zip 里不放 `tests/`、`__pycache__` 和隐藏文件。下载这个脚本，在装了莫提斯的环境里运行：

  ```powershell
  python pack_plugin.py .\zhangsan.osplay -o dist
  ```

## 常见问题

- **「没有 [mortis] 表」/「这不是莫提斯插件包」**：`plugin.toml` 里补上 `[mortis]` 和 `api_version = 1`。
- **「用了不允许的模块」**：插件只能 import 标准库、`pydantic` 和 `mortis.plugin_api`，开进程、联网要经宿主。测试文件放进 `tests/` 就不受这条限制。
- **「不接受这种文件」**：zip 里有白名单以外的文件，提示里点名了是哪个，删掉再压缩。
- **「plugin.toml 的 sources 名单和插件对象不一致」**：清单和 `PLUGIN` 里的 id 要完全对上。
- **「id 要带命名空间」**：导入的插件 id 写成 `作者.名字`。
- **「和某某重名」**：id 在整个注册表里唯一，换一个。
- **「声明了不认识的权限」**：钩子的 `writes` 要写成 `tags:<类别>`，如 `tags:keyword`。
