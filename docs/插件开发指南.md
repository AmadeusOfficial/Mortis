# 插件开发指南

十分钟写出一个能导入莫提斯的插件：从模板开始，改、测、打包、导入、验证。需要查细节时看后面的几份文档：

- 《插件规范》：清单、id、版本、标签规则等所有约定，供查阅。
- 《事件参考》：事件钩子什么时候触发、带什么、有哪些限制。
- 《打包与导入》：zip 的结构、限额、校验顺序、覆盖和卸载。

> **安全提示：** 插件是在本机运行的 Python 代码，和莫提斯同一个进程，没有沙箱。莫提斯的检查只是约定检查，不是安全检查。写插件时请遵守约定，导入别人的插件时只导入你信任的。

## 能写什么

一个插件包可以带下面几样东西，想带几样带几样：

- **来源**：从某个站点取元数据，给某一种数据类型（电影、电视剧、动漫，或别的插件的类型）填字段。
- **播放**：用本机播放器打开文件，或启动游戏文件夹里的程序。
- **事件钩子**：订阅「刮削完成」这类事件，在后台做点事，比如按规则给条目补标签。
- **数据类型**：提交一份字段目录，让莫提斯多管一种东西。

插件不能自带页面、不能建表、不能联网（要经宿主）、不能开进程（要经宿主）。详见《插件规范》的「边界」。

## 准备环境

需要 Python 3.14，并且能 `import mortis.plugin_api`。在莫提斯的仓库里：

```powershell
pip install -e ".[dev]"
```

仓库的 `examples/plugins/` 里有两个能直接用的例子：

| 例子 | 内容 |
|---|---|
| `hello_source` | 最小的来源插件，只有一个 `plugin.toml` 和一个 `__init__.py` |
| `tag_rules` | 来源加钩子的组合插件：订阅 `scrape.finished`，按片长和年份给标签 |

两个例子里的站点地址（`api.example.com`）都是编出来的，装上之后搜不到东西，只演示写法。

## 1. 从模板开始

复制 `examples/plugins/hello_source` 到你自己的目录，比如 `my_plugin/`。目录结构：

```
my_plugin/
  plugin.toml
  __init__.py
  tests/
    test_my_plugin.py
```

`plugin.toml`：

```toml
id = "example.hello_source"
name = "示例来源"
version = "0.1.0"

[mortis]
api_version = 1
```

要改的第一件事是 **id**：写成 `作者.名字`，小写字母、数字和下划线，一个点，字母开头，比如 `zhangsan.my_source`。`mortis.*` 和 `builtin.*` 保留给宿主。**id 一旦有人用过就不能改**：快照、设置、标签来源都按它存。名称（`name`）和版本以后随时可以改。

`[mortis]` 表必须有，`api_version` 现在写 `1`。

## 2. 写代码

`__init__.py` 里定义 `PLUGIN`。最小的来源插件是一个 `SourcePlugin` 子类加三个方法：

```python
from typing import Any

from mortis.plugin_api import Hit, Host, SourceError, SourcePlugin

API = "https://api.example.com/hello"


class HelloSource(SourcePlugin):
    id = "example.hello_source"          # 和 plugin.toml 的 id 一样
    name = "示例来源"
    data_type = "movie"                  # 服务哪个数据类型
    provider = "example_hello"           # 外部编号的名字

    def search(self, host: Host, title: str) -> list[Hit]:
        data = host.get_json(f"{API}/search", params={"q": title})
        return [Hit(external_id=str(r["id"]), title=r["title"]) for r in data.get("results", [])]

    def fetch(self, host: Host, external_id: str) -> dict[str, Any]:
        data = host.get_json(f"{API}/movies/{external_id}")
        if not isinstance(data, dict) or "title" not in data:
            raise SourceError("示例来源里没有这一条")
        return data                      # 整份存成快照

    def candidates(self, raw: dict[str, Any]) -> dict[str, Any]:
        # 只从快照取值，不联网。键必须是电影字段目录里有的。
        return {"tagline": raw["tagline"]} if raw.get("tagline") else {}


PLUGIN = HelloSource()
```

要点：

- **联网只用 `host.get_json`、`host.post_json`、`host.get_text`**，不要自己 `import urllib.request`、`socket`。宿主负责代理、限速和任务记录。
- **失败就抛 `SourceError`**，消息写给用户看，不带令牌。不要吞掉异常后返回空结果。
- **`candidates` 不能联网**：再次刮削时宿主只对已有快照调用它。
- 只能 import 标准库、`pydantic` 和 `mortis.plugin_api`；包内模块之间用相对导入。
- `candidates` 返回值的格式、字段目录的写法，见 `mortis.plugin_api` 开头的注释（`src/mortis/plugin_api/__init__.py`）。

单个对象的简写 `PLUGIN = HelloSource()` 要求对象的 `id` 等于 `plugin.toml` 的 `id`，并且 `plugin.toml` 里不再列 `[[sources]]`。想带多样东西，用 `Plugin(...)`，并在清单里把每一项列出来，见第 6 步。

## 3. 写测试

用 `mortis.plugin_api.testing` 里的假宿主，不连网：

```python
from mortis.plugin_api.testing import FakeHost

host = FakeHost(responses={f"{API}/search": {"results": [{"id": 7, "title": "你好电影"}]}})
hits = PLUGIN.search(host, "你好")
assert hits[0].external_id == "7"
assert host.requests[0].params == {"q": "你好"}
```

`FakeHost` 按完整地址（不含查询参数）返回你给的响应，并记下插件发出的每个请求；没登记的地址会让测试失败。播放插件用 `FakePlayerHost`，钩子用 `FakeHookHost`。

测试放在插件目录的 `tests/` 里（或命名为 `test_*.py`）：加载时不检查也不加载，打包时不放进 zip，所以测试里可以 `import pytest`。`examples/plugins/hello_source/tests/test_hello_source.py` 是完整的例子，里面还演示了怎么把插件目录当成一个包加载。运行：

```powershell
python -m pytest examples/plugins/hello_source/tests
```

录下来的真实响应只保留用得到的部分，去掉令牌和个人信息。

## 4. 打包

```powershell
python scripts/pack_plugin.py my_plugin -o dist
```

脚本会用导入时同一套规则检查：清单、import 约定、文件类型、大小限额，再在临时目录里装一遍确认清单和代码对得上。通过后输出 zip 路径和包哈希；不通过时用中文说明原因。

zip 里不会放 `tests/`、`__pycache__` 和隐藏文件。更多规则见《打包与导入》。

## 5. 导入和验证

1. 打开莫提斯的 设置 → 插件管理，点「导入插件（zip）」，选择 zip。
2. 看预览：插件名称、提供的能力、订阅的事件和声明的权限、文件清单和哈希。核对包哈希和脚本输出一致。预览阶段不执行插件的任何代码。
3. 勾选「我信任这个插件」，确认。这时莫提斯才会试运行插件（import 一遍）。
4. 全新安装不用重启，会直接出现在插件列表里；覆盖升级需要重启莫提斯。

验证：

- 来源插件：到 设置 → 来源 找到它，需要的话填设置和密钥；在测试库里刮一条，在详情页看各字段的值和来源。
- 钩子：刮削完成后，任务页里会出现类型为 `hook` 的任务，点开能看到日志；失败的话原因在任务日志里。
- 出问题时：插件列表里有错误信息，最常见的是清单和 `PLUGIN` 里的对象对不上。

开发时想快速试，也可以不打包，把插件文件夹直接放进数据目录下的 `plugins/`，在设置页点「重新加载插件」，改了代码再点一次就生效，不用重启。手动放的插件同样要有 `[mortis]` 清单。

## 6. 再进一步：来源加钩子

`examples/plugins/tag_rules` 展示怎么在一个包里同时带来源和钩子。`plugin.toml` 里把每一项列出来：

```toml
id = "example.tag_rules"
name = "示例：按规则补标签"
version = "0.1.0"

[mortis]
api_version = 1

[[sources]]
id = "example.tag_rules_films"
name = "示例片长来源"
data_type = "movie"

[[hooks]]
id = "example.tag_rules_tagger"
event = "scrape.finished"
data_types = ["movie"]
writes = ["tags:keyword"]
```

`__init__.py` 里：

```python
from mortis.plugin_api import Plugin

from .hook import RuleTagger
from .source import FilmSource

PLUGIN = Plugin(sources=(FilmSource(),), hooks=(RuleTagger(),))
```

清单里的 `[[sources]]`、`[[hooks]]` 要和代码里的对象按 id 一一对上，多了少了都会加载失败。

钩子是一个 `HookPlugin` 子类，实现 `on_event(host, event)`：

```python
class RuleTagger(HookPlugin):
    id = "example.tag_rules_tagger"
    name = "示例：按规则补标签"

    def on_event(self, host: HookHost, event: Event) -> None:
        if not isinstance(event, ScrapeFinished):
            return
        item = host.get_item(event.item_id)
        if item is None:
            return
        wanted = wanted_tags(item)               # 按当前字段算出应该有的标签
        if wanted:
            host.add_tags(item.id, "keyword", wanted)   # 已经加过的不会重复写
```

几件要记住的事（细节见《事件参考》）：

- **只能写清单里声明了的权限**：`writes = ["tags:keyword"]` 才能写 `keyword` 类标签。
- **只管自己名下的标签**：你加的标签记在你的名下，只能撤自己加的；刮削和用户加的标签你碰不到。用户删除过的标签、被锁定的字段，宿主会拒绝写入并在结果里告诉你，这不是错误。
- **写成幂等的**：同一个条目重新刮削会再触发一次事件，处理多少次结果都要一样。
- **钩子是异步的、有限额的**：每次事件最多联网 5 次、调用标签接口 20 次；连续失败 3 次会被自动停用；超时只记录不强杀。
- 钩子测试用 `FakeHookHost`，它按真宿主的规则处理权限、锁定、所有权和额度，见 `examples/plugins/tag_rules/tests/`。

## 常见问题

- **「没有 [mortis] 表」**：`plugin.toml` 里补上 `[mortis]` 和 `api_version = 1`。
- **「用了不允许的模块」**：插件只能 import 标准库、`pydantic` 和 `mortis.plugin_api`，开进程、联网要经宿主。测试文件放进 `tests/` 就不受这条限制。
- **「plugin.toml 的 sources 名单和插件对象不一致」**：清单和 `PLUGIN` 里的 id 要完全对上。
- **「id 要带命名空间」**：导入的插件 id 写成 `作者.名字`。
- **「和某某重名」**：id 在整个注册表里唯一，换一个。
