# 事件参考

事件钩子让插件在宿主做完一件事之后跟着做点事，比如刮削完成后按规则给条目补标签。本文写每个事件什么时候发、带什么字段，钩子怎么运行、有哪些限额、什么时候被停用，以及写标签时容易踩的坑。

先看《插件开发指南》和《插件规范》。类型的完整说明在 `src/mortis/plugin_api/`（`events.py`、`hooks.py`）的注释里。

## 工作方式

- **发布订阅，只订阅。** 钩子不能中断、改写或延迟宿主的流程。
- **事件在库提交之后发布。** 钩子拿到事件时，对应的改动已经写进库；用 `host.get_item` 读到的是最新的值。
- **钩子在后台任务里异步执行。** 每个「事件 × 订阅它的钩子」排成一个类型为 `hook` 的任务，出现在任务页里，有日志、可以取消、失败有记录。任务的优先级比刮削、整理低，不抢它们的位置。事件不保证实时，也不保证投递的先后顺序。
- **事件会重复。** 同一个条目重新刮削、整理，都会再发一次事件；事件是在任务结束时才排的，任务被取消、条目已被删除时可能根本不发。处理函数要写成幂等的（见下文）。
- **事件只带编号和必要的字段**，不带整条记录。要更多信息用 `host.get_item(item_id)`。
- 事件对象都是 Pydantic 模型，不可变（`frozen`），忽略多余字段；以后新增的字段都有默认值，旧插件不受影响。`event.type` 是 `EventType`（`StrEnum`），可以直接和字符串比较：`event.type == "scrape.finished"`。
- 一个钩子对象订阅一个事件，在 `plugin.toml` 的 `[[hooks]]` 里写 `event`。`data_types` 限定数据类型：不写表示不限；写了名单，数据类型不在名单里的事件不投递，没有数据类型的事件也不投递。

## 设置和密钥

钩子类可以声明 `Settings`、`Secrets`（Pydantic 模型），写法和来源插件一样，表单支持的结构见《插件规范》的「设置表单」。

- 设置页在 设置 → 插件管理 的钩子行里有「设置」按钮，展开后按模型画表单。
- 按**钩子 id** 存：设置在设置文件的 `[sources.<钩子 id>]`，密钥在密钥文件的同名节。同一个包里的几个钩子各存各的。
- 钩子里用 `host.settings`、`host.secrets` 读校验过的实例。每次事件重新读，保存后下一次事件就用新值，不用重新加载插件。
- 没保存过时是模型的默认值；文件里的值被手改坏、通不过校验时，也退回默认值，并在任务日志里记一条（只写出错的位置，不写值）。
- 没声明的钩子，`host.settings`、`host.secrets` 是空模型。
- 测试里给 `FakeHookHost(hook=钩子, settings={...})`：传 dict 时按这个钩子的 `Settings` 校验，不传就是默认值；也可以直接传模型实例。
- 这两个属性是后加的，用到它们的插件要在 `plugin.toml` 里写 `min_mortis_version`。

## 事件清单

所有事件都有 `type` 和 `data_type`。`data_type` 是条目所属数据类型的 id，没有条目的事件为空字符串。下表只列各自特有的字段，没写默认值的整数字段默认都是 `0`。

### item.created

扫描识别后新建了一个条目（电影、剧或插件类型的条目）。

| 字段 | 说明 |
|---|---|
| `item_id` | 新建条目的编号 |
| `library_id` | 所在媒体库 |

和这次扫描的 `scan.finished` 一起，在扫描任务结束时发布。此时条目通常还没刮削，字段是空的；要等刮削完成再做事，订阅 `scrape.finished`。已经存在的条目被再次扫描到，不发这个事件。

### scan.finished

一次扫描整理任务结束。

| 字段 | 说明 |
|---|---|
| `library_id` | 媒体库 |
| `found` | 扫描到的条目数 |
| `added` | 新增的数量 |
| `removed` | 移除的数量 |
| `matched` | 识别成功的数量 |
| `unmatched` | 没能识别的数量 |

### scrape.started、scrape.finished、scrape.failed

一个条目的刮削。三个事件的字段相同，`scrape.failed` 多一个 `error`。

| 字段 | 说明 |
|---|---|
| `item_id` | 被刮削的条目（剧集刮削时是作品条目） |
| `library_id` | 所在媒体库 |
| `task_id` | 刮削任务的编号 |
| `force` | 是不是强制重新刮削 |
| `error` | 仅 `scrape.failed`：给用户看的失败原因 |

- 电影、剧集和插件数据类型的刮削都会发，不管走的是哪条流水线；都在刮削结束、库已提交之后才发布。
- **`scrape.started` 不是刮削开始的那一刻**：它和 `finished` 或 `failed` 一起在刮削结束后发布，同一次刮削先排 `started`、再排 `finished` 或 `failed`。想要「刮完了」的信号订阅 `scrape.finished`。
- 刮削被取消、条目已被删除时不发布。

### arrange.finished

一个条目的整理（改名、写 NFO 和图片）完成。

| 字段 | 说明 |
|---|---|
| `item_id` | 条目 |
| `library_id` | 所在媒体库 |
| `task_id` | 整理任务的编号 |
| `renamed` | 改名的文件数 |
| `written` | 写出的文件数 |

钩子写标签引起的静默 NFO 重写不发这个事件（见「防循环」）。插件数据类型不整理，也没有这个事件。

### play.started

已经用播放插件打开了一个文件或启动了一个程序。打开失败、需要用户选候选的时候不发。

| 字段 | 说明 |
|---|---|
| `item_id` | 条目 |
| `file_id` | 打开的文件 |
| `player` | 播放插件的 id |

### task.failed

一个任务失败了。

| 字段 | 说明 |
|---|---|
| `task_id` | 失败的任务 |
| `task_type` | 任务类型，比如 `scrape`、`organize`、`arrange` |
| `item_id` | 任务带了条目编号时才有，否则是 `0`；有条目时 `data_type` 也会带上 |
| `error` | 失败原因，最多 500 个字符 |

钩子任务自己失败、钩子引起的静默整理失败，都不触发它；取消不算失败。

## 限额

钩子只能做很有限的事，并且每次事件都有额度。**额度按「一个钩子处理一个事件」计，不跨事件累计**，超出时抛 `HookLimitError`，当次处理失败。

| 项目 | 上限 |
|---|---|
| 联网（`get_json`、`post_json`）次数 | 5 次 |
| `get_item` 次数 | 50 次 |
| `add_tags`、`remove_tags` 合计次数 | 20 次 |
| 一次调用处理的标签数 | 50 个 |
| 一次事件处理的标签总数 | 200 个 |
| 标签名长度 | 64 个字 |
| 一次响应的大小 | 1,000,000 字节 |
| 连接超时 | 5 秒 |
| 读取超时 | 10 秒 |

调度上的限制：

- 同一个插件的钩子同时只跑一个。
- 全局同时最多跑 2 个钩子任务。
- 排队中的钩子任务最多 200 个，超出的事件被丢弃，只记日志，不会重试。
- 钩子任务和刮削等任务共用任务机制，但优先级更低。

默认值定义在 `mortis.plugin_api.hooks.HookLimits`，测试里的 `FakeHookHost(limits=...)` 可以换成更小的值。

## 熔断

- **连续失败 3 次，自动停用这个钩子。** 钩子抛出任何异常（包括超出额度、越权、联网失败），算一次失败；成功处理一次事件，计数清零。
- 熔断时，钩子在进程里立即停用，并且把钩子 id 写进设置文件的 `[plugins] disabled`，重启后依然停用。只影响这一个钩子，同一个包里的其他钩子、来源和播放不受影响。
- 重新启用：把这个钩子的 id 从设置文件 `[plugins]` 的 `disabled` 列表里删掉，然后在设置页重新加载插件（或重启），失败计数随之清零。
- 排队中的任务在跑之前会再检查一次：钩子已停用或被移除的，任务直接跳过并标成成功。

## 超时只记录，不强杀

钩子在宿主进程的线程里运行，**宿主没办法强行结束一段卡死的 Python 代码**。所以：

- 联网有连接和读取超时，其他代码没有。
- 处理一个事件用了超过 60 秒，宿主只在任务日志里记一笔，并按一次失败计入熔断；钩子不会被打断。
- 用户取消任务只在钩子开始前生效，已经在跑的钩子不会被打断。
- 卡死的钩子会一直占着它所在插件的那一个并发位，也占着全局 2 个位置之一。不要在钩子里写死循环、无限等待。

## 防循环

- **钩子任务不再发布事件。** 钩子里的改动不会再触发别的钩子。
- **钩子失败不触发 `task.failed`。**
- 钩子写标签后，已经整理过的条目会重写 NFO；这次重写是静默的：不发布 `arrange.finished`，失败也不触发 `task.failed`。
- 标签的增删本身不发布任何事件。

所以你的钩子不会因为自己的写入被再次唤醒；但重新刮削会再次触发 `scrape.finished`，这就是要写成幂等的原因。

## 联网限制和 SSRF 防护

钩子联网只能用 `host.get_json` 和 `host.post_json`，走宿主的 HTTP 客户端（代理等设置和来源插件一致），只能拿到 JSON。

- 只允许 `http` 和 `https`；地址里不能带账号密码；必须有主机名。
- **拒绝本机和内网**：`localhost`，以 `.localhost`、`.local`、`.internal` 结尾的域名，以及解析出来不是公网的地址（回环、私网、链路本地、保留地址等）。域名先在本机解析，解析出的每个地址都要通过检查。违反时抛 `HookLimitError`。
- **跳转也检查**：宿主自己跟随跳转，最多 3 次，每一跳都重新检查地址；跳到另一个主机时丢掉 `Authorization` 和 `Cookie` 头；`301`、`302`、`303` 跳转后非 `GET` 请求会改成不带正文的 `GET`。
- 响应超过 1,000,000 字节直接中断（先看 `Content-Length`，读取时再按实际字节数检查）；对方返回 4xx、5xx 或者不是 JSON，抛 `HookError`。
- 每次事件最多联网 5 次，请求的网址（不含查询参数）会写进任务日志。
- 使用代理软件的 fake-ip 模式时，域名会被解析到 `198.18.0.0/15`，这一段只对域名放行，直接写这一段的 IP 地址不放行。

这是尽力而为的防护，不是沙箱：域名解析和实际连接之间有极短的窗口（DNS 重绑定），插件本身也仍然和宿主同进程运行。

## 标签：覆盖的坑和幂等写法

写标签用 `host.add_tags(item_id, tag_kind, names)` 和 `host.remove_tags(item_id, tag_kind, names)`，需要在 `[[hooks]]` 里声明 `writes = ["tags:<tag_kind>"]`。电影的标签类别有 `genre`、`country`、`studio`、`keyword`、`language`，插件数据类型用自己字段目录里的 `tag_kind`。完整规则见《插件规范》的「标签来源规则」，这里是写钩子时要记住的：

- **结果不是错误。** 两个方法都返回 `TagResult`：
  - `applied`：增时是实际新增的，删时是实际撤掉的；
  - `unchanged`：增时是本插件早就加过的，删时是本来就没有的；
  - `locked`：字段被锁定，整批跳过；
  - `removed_by_user`：用户手动删除过，被忽略；
  - `not_owned`：删的是别人名下的标签，被拒绝。
  钩子不必重试这些。
- **你的标签记在包 id 名下。** 同一个包里的几个钩子共享它；刮削结果和用户手动加的标签你碰不到，也撤不掉。
- **同一个标签可以同时有多个来源。** 你撤掉自己的来源后，如果刮削结果里也有这个标签，它仍然显示。`remove_tags` 返回 `applied` 只代表你的来源撤了，不代表标签从条目上消失。
- **用户删除会清掉你的标签，而且补不回来。** 用户删掉一个标签时，所有来源（包括你的）都被清掉；之后你再 `add_tags` 它，得到 `removed_by_user`，不会写入。别想绕过去，这是用户的明确意思。
- **锁定的字段不写。** 标签类别对应的字段被用户锁定时，整批写入被跳过。
- **刮削不会冲掉你的标签。** 重新刮削只替换刮削来源的标签。所以通常不需要在每次刮削后「补写」；但你的规则依赖刮削结果时（比如按片长打标签），就订阅 `scrape.finished`，用最新的字段重新算。
- **读最新的数据。** 钩子是异步的，不要把事件当成条目的快照；总是用 `host.get_item(item_id)` 取当前状态，条目已不存在时返回 `None`。
- 写标签后，已经整理过的条目会静默重写 NFO，所以不要为了「保险」反复写同样的内容；没有变化时不要调用接口，也省额度。

### 幂等写法

同一个事件处理一次和处理很多次，结果必须一样：

1. 用条目当前的字段**算出**这个条目应该有哪些标签，不要依赖「上次做过什么」。
2. `add_tags` 想要的标签：已经加过的会返回 `unchanged`，不会重复写。
3. 规则变了、要撤掉不再适用的旧标签时，只在**本插件可能加过的标签范围**里撤，并且只撤现在还显示着的；不是你加的会被拒绝，无害。
4. 没有变化就不调用接口。

示例见莫提斯仓库的 [`examples/plugins/tag_rules/`](https://github.com/AmadeusOfficial/Mortis/tree/main/examples/plugins/tag_rules)（`rules.py` 定义设置模型并按设置算标签，`hook.py` 从 `host.settings` 读规则、写标签，`tests/` 用 `FakeHookHost` 验证默认和自定义规则、关掉的规则、幂等、撤旧标签、不碰别人的标签、被锁定和被用户删除时的表现）。

## 钩子失败的表现

- 钩子抛出异常：对应的 `hook` 任务标记为失败，任务日志里有完整的堆栈和 `[钩子名称] ...` 的日志，失败信息形如「钩子 X 出错：ValueError: ...」。**刮削和其他钩子不受影响**，已经提交的库也不会回滚。
- 连续失败 3 次，钩子被自动停用（见「熔断」）。
- 事件内容不认识（比如旧版本留下的排队任务）：任务失败，提示事件内容不认识。
- 钩子在运行时被停用或移除：任务跳过，标成成功。
- 联网、标签、读条目超出额度：抛 `HookLimitError`；写了没声明的权限：抛 `HookPermissionError`；其余宿主能力的失败（条目不存在、对方返回错误、解析不了域名）抛 `HookError`。三者都带给用户看的消息，并且都是 `HookError` 的子类，钩子里可以捕获它们自己处理。注意：吞掉异常意味着宿主看到的是这次处理成功，失败计数会清零，所以不要用它掩盖真正的错误。
